# 12 — 每日运势与个性化内容设计（E10）

> 版本：v1.0 · 定稿日期：2026-08-18
> 需求来源：产品 2026-08-18 拍板——
> ① 以后端为唯一真源，app 与小智服务都拉后端接口；
> ② 内容由 LLM 联网检索互联网信息、简单处理后，按不同星座生成下发；
> ③ 新增主人八字命理输入（app 录入，后端建表）；
> ④ 事业 / 财运 / 学业 / 情感四维度按星座分析；
> ⑤ 所有分析基于 LLM。

## 1. 目标与原则

- 每设备个性化结构内容三类：**打招呼素材**、**每日星座运势**（四维度）、**八字命理运势**（四维度）。
- 后端生成、存储、下发；app 走用户 API 展示；小智经 `persona_pack`（300 秒刷新）注入对话，**7 字段契约不变**。
- 红线沿用：全部内容由 agent-worker 异步生成、按日缓存；**不进实时语音路径**，不在通话中算星盘（docs/05 已禁）；八字属敏感数据，可见性/导出/删除随用户数据策略执行。
- 无 LLM 或生成失败时：对话与 app 均降级为空态，不阻塞任何既有链路。

## 2. 内容分层

| 层 | 表 | 粒度 | 生成任务 | 说明 |
|----|----|------|----------|------|
| L1 共享星座层 | `daily_sign_fortunes` | (fortune_date, sign) 全站唯一 | `daily_sign_fortune`（每日每星座 1 次） | LLM 联网检索当日星象/运势信息 → 汇总 → 按 12 星座 × 4 维度生成短文案；全设备共享，不为单设备重复生成 |
| L2 设备个性层 | `device_daily_contents` | (device_id, content_date, kind) 唯一 | `daily_device_content`（每日每设备 1 次） | kind ∈ `greeting` / `bazi_fortune`；输入 = 该设备 persona（星座/MBTI/dossier）+ 精选 active 记忆 + 昨日 daily_summary + L1 当日星座运势 + 主人八字（如有） |

L2 依赖 L1：`daily_device_content` 发现当日 L1 缺失时先入队 L1、自身延迟重试（不消耗重试次数，沿用 2026-08-16 的延迟重试策略）。

docs/02 中原预留的 `persona_daily_context` 表由本设计的 `device_daily_contents` 取代，不再单独建设。

## 3. 表结构（docs/02 已登记；迁移生成后须人工 review 再执行）

### daily_sign_fortunes（共享星座运势）

`id, fortune_date(date), sign(text, 12 星座稳定键), payload(jsonb), llm_model, created_at`
唯一约束 `(fortune_date, sign)`；查询索引 `(fortune_date)`。

`payload` 钉死键：

```json
{
  "overall": "一句总述",
  "career": "事业", "wealth": "财运", "study": "学业", "love": "情感",
  "source_digest": "LLM 检索到的当日信息一句话摘要（便于运营排查，不含链接正文）"
}
```

### device_daily_contents（设备级个性化内容）

`id, device_id(FK), content_date(date), kind(text), payload(jsonb), created_at`
唯一约束 `(device_id, content_date, kind)`；查询索引 `(device_id, content_date)`。

- `kind=greeting`：`payload={"text": "今日开场可自然提到的素材（1~2 句）"}`
- `kind=bazi_fortune`：`payload={"overall": "...", "career": "...", "wealth": "...", "study": "...", "love": "..."}`

### owner_bazi_profiles（主人八字，一设备一行）

`device_id PK/FK, calendar_type(solar|lunar), birth_date(date), birth_time(time, 可空=时辰未知), birth_place(text, 可空), gender(text, 可空), bazi_text(text, 可空), created_at, updated_at`

- 首版挂在设备上（运势由该设备的宠物讲出）；用户多设备场景后续可提升为 user 级，届时迁移归属。
- `bazi_text` 为 LLM 排出的四柱文本缓存，避免每次生成重排；出生信息变更时清空重排。
- **敏感数据**：原始生辰只供 worker 生成使用；注入对话与返回 app 的是运势结论，不是生辰原文；纳入数据导出与删除范围。

## 4. Worker 任务（agent_tasks 新 kind，复用现有 LLM 配置）

### daily_sign_fortune

1. LLM 联网检索当日星象/运势类公开信息（搜索源见 §8 待决）；
2. LLM 汇总为当日信息摘要（`source_digest`）；
3. 按 12 星座分别生成四维度（事业/财运/学业/情感）+ 总述短文案，逐行写入 `daily_sign_fortunes`（已存在则跳过，幂等）。

### daily_device_content

1. 读设备 persona、dossier、近 36h daily_summary、精选 active 记忆、当日 L1 星座运势；
2. 生成 `greeting`（1~2 句开场素材，人设口吻，自然引用运势/记忆，不堆砌）；
3. 若存在 `owner_bazi_profiles`：结合当日干支与主人八字生成 `bazi_fortune` 四维度；`bazi_text` 为空则先排盘缓存。

### 触发（懒生成，不新增调度器）

每日首次发生以下任一事件时检查当日内容，缺失即入队：

- app `GET /devices/{id}/fortune/daily` 请求；
- `POST /api/internal/devices/seen`；
- 会话结束入队 `daily_summary` 时。

八字信息被 `PUT` 修改后，当日 `bazi_fortune` 标记重生成（删除旧行重新入队）。

## 5. API（契约已登记 docs/06）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/PUT | `/devices/{id}/bazi` | 主人八字读写（用户 JWT + 设备归属校验）；未录入 GET 返回 404 |
| GET | `/devices/{id}/fortune/daily?date=` | 当日运势聚合：星座四维度 + greeting + 八字四维度；缺日期默认今天 |

小智侧**无新接口**：内容经 `persona_pack` 下发（见 §6），小智 300 秒刷新自动生效，无需改仓。

## 6. 对话注入（契约不变）

- `compile_profile` 读取当日 `greeting` 与星座运势总述，经 `compile_persona` 已有的 `daily_context` 参数拼入 `system_prompt_fragments` 末尾。
- 写法为**引导语**（"今天开场时可以自然地提到……"），由模型组织语言，不是固定 TTS 文本——避免每天每台设备同一句录音感。
- persona_pack 缓存 key 按 docs/03 已含 `daily_date`，日切后自动重编译。
- C5 `/api/internal/context/device` 职责不变（只装记忆与摘要），不重复注入运势。

## 7. 隐私与安全

- 八字原始数据不出后端：不进 persona_pack 全文、不进 C5、不进日志；日志只记元数据（红线 6）。
- `bazi` 写操作不写审计正文，仅记字段变更键名。
- 导出（E8 解除 501 后）与账号/设备数据删除须覆盖 `owner_bazi_profiles` 与 `device_daily_contents`。
