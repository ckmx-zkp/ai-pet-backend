### 2026-08-18 E10.3 运势增强上线（联网检索真实链路待修复）

- 部署提交：`3a94d8a`；web-api/agent-worker 已重建，`/healthz` 200；新增 admin 只读 `GET /admin/devices/{id}/fortune/daily`（无 token 401 已验证）。无表结构变更、无迁移。
- **MiniMax 联网实测结论**：OpenAI 兼容端点（`/v1/chat/completions`）不支持服务端检索。Anthropic 端点对照（官方天气问法）：`MiniMax-M3` 返回 `server_tool_use`/`web_search_tool_result`；`MiniMax-M2.7`、`MiniMax-M2.7-highspeed`、`MiniMax-M2.5` 均 `stop_reason=tool_use` 且工具名为 `plugin_web_search`（不检索）。配置：`FORTUNE_SEARCH_ENABLED=true`、`FORTUNE_SEARCH_MODEL=MiniMax-M3`；12 星座 JSON 分发走现网 `LLM_MODEL`（M2.5），不需要旗舰模型写文案。
- **已知问题（待修复→已改为两步）**：同一次请求既检索又输出 12 星座 JSON 时，M3 可能跳过检索或截断 JSON。现改为 M3 只做检索摘要，再由 `LLM_MODEL` 生成 JSON；检索未执行仍延迟重试。
- 已生效：每日定时预生成（东八区 05:00 后、15 分钟间隔扫描，`daily_prefill_done` 日志）；每日内容切日统一东八区（`pet_common/dates.py`）；greeting 当日缺失回退昨日。

## 4. 日常运维命令（在服务器上执行）

```bash
cd /opt/ai-pet/ai-pet-backend

# 更新部署（代码 push 后）
git pull && docker compose up -d --build

# 数据库迁移
docker compose run --rm web-api alembic upgrade head

# 看状态 / 日志
docker compose ps
docker compose logs -f web-api        # 或 memory-mcp / agent-worker

# 进入数据库
docker exec -it ai-pet-backend-postgres-1 psql -U postgres -d ai_pet

# 重启单个服务
docker compose restart web-api
```
