# 13 — 主动播报与下发测试设计（E11）

> 版本：v1.0 · 定稿日期：2026-08-18
> 需求来源：产品 2026-08-18 拍板——
> ① 主动播报考量在 app 端配置：是否开启、播报内容类型（情感关心、运势分析等）；
> ② 每日定时器预生成内容（见 docs/12 §4）；
> ③ admin 提供测试功能：一键下发一段话 → 小智唤醒设备并自动播放，用于端到端验证。

## 1. 目标与边界

- 设备从"只会被唤醒后回答"扩展到"在配置允许时主动开口"：播报情感关心、当日运势等短内容。
- **下行通道沿用既有集成方向**：所有连接都由小智侧发起，backend 不主动连接小智——播报采用**小智轮询拉取**模式（见 §4）。backend 只负责配置存储、内容生产、消息队列与状态跟踪。
- 仅在设备**在线**（与小智保持 WS 连接）时可送达；设备离线/深度睡眠时消息滞留队列，超 24h 置 `expired`。
- 播报绝不插入正在进行的语音会话（小智侧约束：会话中有新播报则排队到会话结束）。

## 2. 表结构（docs/02 已登记）

### device_broadcast_prefs（每设备播报配置，app 可编辑）

`device_id PK/FK, enabled(bool, 默认 false), kinds(text[], 子集 of care|fortune), send_window(text, 如 "08:00-21:00"), created_at, updated_at`

- 默认关闭，app 显式开启；`kinds` 为空视为全不播。
- 发送窗口按东八区解释；窗口外产生的播报顺延到下一窗口。

### broadcast_messages（播报消息队列）

`id, device_id(FK), kind(greeting|care|fortune|test), text(text), priority(int, test=0 最高), status(pending|delivered|played|failed|expired), created_at, delivered_at, played_at`
索引 `(device_id, status)`；每设备 pending 上限 5 条，超出淘汰最旧的非 test 消息。

## 3. 内容生产（worker，复用每日定时器）

- 每日定时预生成时，对 `enabled=true` 的设备按 `kinds` 产播报文案：
  - `care`（情感关心）：近 36h `daily_summary` 的情绪与 follow_up + active 记忆，1~2 句人设口吻；
  - `fortune`（运势分析）：当日 L1 星座运势 + L2 八字运势（如有），1~2 句；
  - `greeting`：复用 docs/12 的当日 greeting（小智开机首句播报用，见 §5）。
- 文案写入 `broadcast_messages`（status=pending）。生成失败走既有延迟重试。

## 4. 下发契约（内部接口，小智轮询，契约先行已登记 docs/06）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/internal/devices/{uid}/broadcasts/pending?limit=` | 拉取该设备 pending 消息（按 priority、created_at 排序，limit 上限 5） |
| POST | `/api/internal/devices/{uid}/broadcasts/{id}/ack` | 回执 `{status: delivered|played|failed}`；played 写 played_at |

- 拉取时机（小智侧实现）：设备连接建立时 + 连接中每 5 分钟一次。
- `test` 消息由 admin 测试接口产生（§6），priority 最高，下一轮轮询即被取走；测试即时性取决于轮询间隔（最坏 5 分钟，可接受）。
- backend 不判断设备在线与否；小智只在设备在线时拉取。消息不落对话历史、不经脱敏（内容是 backend 自产文案）。

## 5. 小智侧配合（看板 X4/X5）

- **X4 播报通道**：实现轮询拉取 + TTS 播报 + ack 回执；会话中排队；设备闭眼休息状态跳过当次（下轮再取）。
- **X5 开机首句**：连接建立拉 persona_pack 后，若 `broadcasts/pending` 有 `greeting`（或 test）消息，优先播报——实现"开机第一句话由后端定制"。
- 小智无需理解播报内容语义，只做运输与播放；失败按既有 BIZ 日志规范记录 outcome。

## 6. admin 测试下发

`POST /api/admin/devices/{id}/broadcast/test`（body 可带自定义 `text`，缺省用内置测试句）：
写入 `kind=test, priority=0, status=pending` 消息，返回 `{id, status}`；admin 轮询/刷新查看状态变化
（pending → delivered → played）。前端按钮与状态展示为 admin D6。

## 7. 用户 API（app A15）

`GET/PUT /devices/{id}/broadcast/prefs`：读写 enabled/kinds/send_window；契约见 docs/06。
