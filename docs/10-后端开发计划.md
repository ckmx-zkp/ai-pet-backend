| # | 缺口 | 决策 | 来源 |

| 1 | 记忆候选无「驳回」 | 加 `POST /devices/{id}/memories/{mid}/reject` | admin 02、app 02 |

## 1. 迭代排期（依赖驱动）

```text
auth ✅ ──► E1 devices ──► E2 persona+KB种子+persona_pack ──► E3 内部集成（旁路）
                                              │                        │
                                              ▼                        ▼
                                        admin M2 点亮          E4 messages（有了真数据）
                                                                         │
                                              ┌──────────────────────────┤
                                              ▼                          ▼
                                        E5 memories+MCP            E6 worker+analyses
                                              └──────────┬───────────────┘
                                                         ▼
                                              E7 admin KB 运营 ──► E8 export 等收尾
```

| Epic | 内容 | 解锁谁 | 验收标准 |
|------|------|--------|---------|
| **E1 devices** | 绑定（device_uid 唯一）、列表（在线/固件/capability）、详情、改名、解绑 | admin M1 完整、app V0.2 设备域 | 绑定→列表→改名→解绑全流程 curl 通过；重复绑定 409 |
| **E2 persona + KB 种子 + persona_pack** | KB 种子数据迁移（四元素+双鱼差分+2 个 MBTI）；`GET/PUT persona`（sun_sign/mbti/overrides/follow_latest）；PersonaCompiler 接真实 KB；`GET /internal/devices/{uid}/persona_pack` 返回 6 字段 schema | **xiaozhi V0.2 最大解锁**（人设注入）、admin M2、app P3 | 设置双鱼+INFP→拉 persona_pack 含 water+pisces 片段+default_emotion；follow_latest 与钉扎行为正确 |
| **E3 内部集成** | `POST /internal/chat/events`（落库前脱敏、会话/消息写表）、`POST /internal/peripheral/events`（覆盖写快照）、`POST /internal/chat/sessions/{id}/end`（摘要任务入队 agent_tasks） | xiaozhi 旁路上线、E4 有数据 | 模拟小智连发事件→库中出现脱敏消息+会话；peripheral 单行覆盖写 |
| **E4 messages** | 历史分页查询（device_id+created_at，from/to/limit）、按日删除+审计 | admin M3、app P5 | 真实旁路数据可按日翻页；删除写审计 |
| **E5 memories + memory-mcp** | 记忆 CRUD、q 搜索、status 筛选、approve/reject；memory-mcp 三工具接真实库（search/add/forget，候选走 candidate） | admin M3、app P4、xiaozhi 记忆工具 | MCP 客户端调 memory.add→candidate；approve 后 search 可见 |
| **E6 worker + analyses** | worker 任务处理器：日摘要、记忆候选提取（调外部 LLM API）；`GET analyses?kind=` | admin M4 卡片、app P6 日运 | 手动塞一个 summarize 任务→analyses 出现结果卡片 |
| **E7 admin KB 运营** | zodiac CRUD、发布（version++、409 冲突）、feedback accept/ignore | admin M4 KB | 草稿→发布→版本递增；钉扎设备不受影响 |
| **E8 收尾** | export（异步）、questionnaire、数据保留清理任务（90/180 天） | app P8 | 按需 |
| **E9 社交（V0.3）** | device_social_keys/device_friendships 两表（提前随近次迁移建掉）+ social events/friends 三端点 + 绑定下发 social_secret；设计见 docs/11 | 固件 BLE、app 好友页 | 契约已定稿，实现排 V0.3 |

## 2. 排期理由

1. **E1 先行**：所有接口都挂在 device 上，且 admin M1（Codex 在等）只差设备接口
2. **E2 是本项目灵魂**：人设注入是差异化价值，且是 xiaozhi-server 唯一的硬依赖；KB 种子不做，编译器无米下锅
3. **E3 紧随**：旁路通了才有真实对话数据，E4/E5/E6 才有原料；早通早暴露联调问题
4. **E4/E5 并行面小**可连做；**E6 依赖 E3 的数据**；**E7 最独立放后**
