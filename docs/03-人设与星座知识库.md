# 03 — 人设与星座知识库

## 主体

- `persona_profiles` 是**宠物**人设（一设备一行），只允许直选写入星座/MBTI。
- `owner_profiles` 是**主人**档案（一用户账号一行，多设备共享）。问卷、趣味测试、八字、星盘写入主人。
- `persona_profiles.bond` 是**这只宠物与主人的关系**（一设备一份，不能挂到账号上：同一主人对不同宠物可以是爱子或逆子）。worker 根据脱敏对话和已确认记忆更新；用户也可直选。
- `persona_pack` 身份行只使用宠物星座/MBTI；主人信息另以「这些是主人的信息」片段注入；关系另以「你和主人此刻的关系是…」注入。7 字段契约不变。

## 分层模型

```text
element(water)          ← 持续提升主战场
  └─ sign(pisces)       ← 只写差分
       + mbti(INFP)
       + overrides
            ↓ PersonaCompiler
       persona_pack
```

## PersonaCompiler

**输入：** published 的 element + sign + mbti + profile.overrides + 可选 daily_context  
**输出：** 见 `xiaozhi-server/docs/03` 的 `persona_pack` JSON  
**要求：** 纯函数可测；结果可缓存（key=`device_id+kb_version+daily_date`）

## 发布与钉扎

1. 运营编辑 draft → 审核 → `status=published`，version++  
2. `follow_latest=true`：下次编译用最新 published  
3. `follow_latest=false`：钉死 `kb_version`  
4. 可按 element/sign 灰度（配置表或环境开关）  

## 持续提升闭环

```text
对话脱敏 → agent-worker 产 kb_feedback_candidates
  → admin 接受 → 只创建 draft（version++）
  → admin 人工编辑/发布 → 新 published version
  → 未钉扎设备下次会话生效
```

Agent **不得**直接改 published 行。`POST /admin/kb/feedback/{id}/accept` 只落 draft，
发布必须再走 `.../publish`。
